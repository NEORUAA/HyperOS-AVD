## 来宾安装与保数据检查

使用最终分卷及冻结 Installer 1.2.1 创建独立新用户实例。新装默认常亮 `2147483647`、AOD 开启、HWUI `skiavk`，桌面、天气与相册预装路径均存在。32 GiB 配置对应来宾 ext4 总容量 32,925,648 KiB，确认不是只扩磁盘外壳。

新装冷启动中，固定辅助服务三次运行均以状态 0 退出；`iorapd`、`millet_monitor`、`loc_sys_service` 全部自动停止，Millet 能力标志为 0。四个修复 APK / JAR 的来宾哈希一致，启动修复模块不存在，全局 SELinux 为 Enforcing；没有手动重跑脚本或动态追加策略来完成最终验收。三个目标包未出现在本次启动的 crash buffer。

r3 → r4 使用本地原始 r3 镜像创建独立测试用户分区，记录基线后通过最终安装器执行正常备份、兼容检查、切换与冷启动。Android ID、引导完成状态、用户应用包列表、KernelSU 首次安装时间、模拟序列号、测试文件 SHA-256、自定义设置和用户选择均保持一致；旧用户的息屏超时 `7200000`、插电常亮关闭、AOD 关闭未被新装默认值覆盖。升级后三个守护进程同样自动停止，四个修复文件哈希正确，无启动修复模块，SELinux 保持 Enforcing。此验收使用受控测试用户数据，不代表登录账号或每个三方应用的完整功能验收。

## 升级边界

r4 使用 `same-family-forward-v1`，不再逐一列出来源修订号。Installer 1.2.1 支持 r1 / r2 / r3 直接升 r4，以及后续满足兼容检查的更高修订号；修订号不替代固件身份检查。源与目标仍须属于同一 userdata 家族，使用相同加密模板和受支持的固定 OTA 配置。未知固件须增加并验证配置，不能靠改成 r999 绕过。

模块迁移、失败备份和容量检查继续保留。旧 revision 1 实验相机模块仍拒绝跨 OTA 自动迁移；未知模块修订不能静默覆盖。OS3、Pad 和手机版不能互相覆盖，保数据降级仍拒绝。

## 启动修复与性能

前序独立运行检查已确认三个目标崩溃不再出现，缺失接口对应的 `iorapd`、`millet_monitor`、`loc_sys_service` 停止，模拟器标准 GNSS 保留。Settings 滚动修复前后均仅 1 个 jank，p95 均为 10 ms；这些数据证明没有测到滚动性能退化，不宣称渲染帧率提升。短期空闲采样不代表长期性能保证。

本版将对应字节、内核能力策略及固定辅助服务所需 SELinux 许可写入镜像，避免仅靠 userdata 中的测试模块维持修复。系统 APK 保留原签名身份用于只读系统扫描，修改后的 APK 不可作为签名有效的用户更新包侧载；普通用户 APK 验证未改动。

## 临时文件清理

已删除本轮 r1 旧候选、新装和 r3 测试 AVD 登记、测试用户数据与备份，以及 EROFS 解包、raw 构建缓存、专项输入副本和安装器解包目录。收尾清理回收约 42.0 GiB，外置盘可用约 331.1 GiB；保留六个原有 AVD、用户原有备份、可复用的最终工厂镜像、最终上传附件和小体积审计记录。未下载 r1 / r2 旧镜像。

## 限制

按用户要求，来宾实际安装流程仅验证 r3 → r4 与新装；r1 / r2 和未来修订号通过清单及通用规则测试，未完成来宾保数据验收。

本轮自动启动验证使用测试实例的引导跳过，不等同于逐页 OOBE 交互验收。Google 认证通知、登录、Play Integrity、云服务和相机完整功能本版未处理。全局 SELinux Enforcing；固定 init 辅助服务保留 Enforcing，KSU 授权 root shell 的凭据单独带有 permissive 标记。原始含标识的日志、JSON 和数据副本保存在 Git 忽略目录，不公开。
