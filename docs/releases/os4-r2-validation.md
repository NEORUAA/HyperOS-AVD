最终包首次冷启动曾在一个既有第三方原生库的 ext4 读取中等待，5 分钟超时；未观察到崩溃。同一固件和数据同步关闭后，冷启动重试完成引导并通过上述核对，没有重置或删除应用。该 I/O 等待根因尚未确定，不能宣称所有旧数据首次启动都能一次完成。

安装器拆分后，主机测试增至 **80 项通过**，新增独立打包校验、发布类型隔离、分页发现、OS3 旧实例识别、中文边框对齐和菜单选择验证。固件保留此前实际启动验证的冻结 runtime；Installer 1.0.0 是独立下载 / 安装入口，源码与该旧 runtime 的 UI 版本差异符合预期。

独立安装器 ZIP 为 137259 bytes，43 个可移植文件逐项校验通过，ZIP 与 `installer.json` 的 SHA256SUMS 通过。实际中文 PTY 菜单和解压后英文入口均能展示 OS3 / OS4 在线镜像、本地旧实例及独立安装器更新入口；尚无正式安装器发布时提示未发布。测试仅浏览和返回，没有启动或改动已有 AVD，临时解压目录已删除。拆分后的 7 个镜像附件重新校验通过，5 个分卷和 manifest 保持原 SHA-256。

## 验收范围

真实测试只使用新建的 `HyperOS_upgrade_temp` 与 `HyperOS_fresh_temp`，旧版数据来自已有备份的克隆。原始 OS4 镜像、AVD 与备份没有参与切换。

旧版保数据测试抽查应用清单、应用版本、偏好文件、Android ID 和开机引导状态，不代表逐个测试所有应用业务。全新启动没有重新人工完成整段 OOBE。渲染、色彩、动画、相机和音频修复的交互验收依据本聊天中的前序测试与用户确认，本轮未重新进行视觉和持续听音验收。

尚未发布的 v0.2.1 使用本地 `--bundle` 安装；最终 Release 上传后，仍需核对远端附件完整性和自动下载入口。兼容族不变的后续版本复用当前升级机制，未知 Android 大版本与加密模板变化会拒绝自动迁移。
