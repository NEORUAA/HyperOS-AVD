## 保数据升级

使用独立 r2 数据副本完成 r3 安装与多次冷启动，最终 20 个检查项全部通过。14 个保留字段一致，包含 Android ID、完成引导状态、模拟序列号、AOD / 常亮 / 色彩选择、38 项第三方包清单和两个用户文件探针；天气私有目录中的探针文件校验一致。这不代表所有账号登录态、天气数据库或云服务完成验收。

升级保留原始 userdata、QCOW2、加密密钥与 qemu-version 关系；原版 APK 和应用私有数据不卸载。未知 / 旧 revision 1 相机模块会阻止迁移，须先在 r2 更新为匹配 revision 2。其它系列、无安装清单实例及保数据降级均拒绝自动覆盖。

## 扩容与恢复

39 项存储测试包含真实临时 ext4 / QCOW2 磁盘，覆盖有效顶层 overlay、原文件哈希 / UUID / 密钥保留、禁止缩容、打开文件拒绝、依赖 / 空间不足、文件系统检查失败、部分切换中断、完整切换中断、加密后容量证明及后续写入保护。另有来宾助手与管理器测试覆盖解密映射、身份 / 备份 / 超级块、在线增长分支、超时和停机保护。

另重现“虚拟盘 32 GiB、ext4 仅 6 GiB”，修复后 ext4 为 32 GiB，文件探针、UUID、两层密钥、版本标记与 backing 名称保持一致。首次安装会先准备实际文件系统，再交给旧镜像的冻结启动器，避免旧启动代码重新引入相同问题。失败的新数据保留在 `failed-data-*` 供检查，原链与扩容日志保留在 `.userdata-resize-backup-*`。

随后在独立真实 AVD 中刻意创建相同旧盘缺陷。首次启动并加密后，系统内 `/data` 为约 5.8 GiB；完整四层备份后，安装器临时启动同一固件，维护启动后核验解密设备和 ext4 超级块均为 32 GiB，正常冷启动后 `/data` 为约 31 GiB。文件 SHA-256、Android ID、引导状态与模拟序列号保持一致。该实例在维护启动中已完成增长，来宾助手记录 `changed=false`；不将它描述为助手执行 `resize2fs` 的实测，也不宣称直接测量了跨此增长前后的 UUID。

容量证明绑定基础层、密钥和四层 backing 关系；复制 / 恢复数据层后会重新检查来宾系统。宿主机不会对密文运行 ext4 工具。已加密磁盘继续增大虚拟容量（如 32 → 64 GiB）仍会拒绝，原数据保留。

## 最终分卷新装

使用发布分卷通过 Installer 1.2.0 安装独立临时实例，使用 4 GiB / 2 核 / 32 GiB 的测试资源，发布默认仍为 6 GiB / 4 核。首次启动前，实际 ext4 已由 6 GiB 扩至 32 GiB；系统内 `/data` 为约 31 GiB，已核验 boot completed、root / Enforcing、HWUI Vulkan 及预装桌面 / 天气 / 相册。

首启初始化的一次 ADB APK 读取失败在重试后通过。冷启动还发现了加密后的宿主检查误拦截，已补上带基础层 / 密钥校验的历史容量证明；修复后冷启动与完整初始化通过。本轮没有自动走完全部 OOBE 页面，Provision 未禁用，启动器未使用跳过引导参数。最后重新打包的变化仅为宿主运行代码与安装说明，实际镜像和空白模板字节保持一致。

## 交互与限制

前序 r3 测试实例已确认 Settings 的 HWUI Vulkan、锁屏编辑视频预览修复、主副屏 60 Hz、独立背屏窗口，以及原版右边缘返回和双击息屏 / 唤醒；单击不会唤醒。冷启动没有再出现已定位的 goldfish 队列溢出，但短期通过不等于长期稳定性证明。

相机录像仍有掉帧，蓝牙、Google 登录、Play Integrity、小米云服务与全部设备硬件能力未完整验证。全局 SELinux Enforcing，KSU root 域仍为 permissive。原始含用户标识的 JSON、日志、备份和运行时分区保留在 Git 忽略目录，不公开。
